# 여러 사람이 함께 테스트하기

각자 로컬 복사본과 가상환경에서 실행하므로 같은 GitHub 저장소를 받는 것만으로 실행이 충돌하지 않는다. 같은 영상·영역의 중복 분석과 결과 합산은 별도로 관리해야 한다. 현재 CLI에는 중앙 작업 배정·잠금·자동 결과 병합 기능이 없다.

## 두 종류의 테스트

- 설치·재현성 테스트: 같은 작은 영역을 2명 정도에게 의도적으로 배정한다. 같은 코드 커밋·영상·작업 JSON·모델·설정을 사용하고 환경과 결과 차이를 비교한다. 합산 대상이 아니다.
- 범위 확장 테스트: 사람마다 서로 다른 도엽 또는 영역을 배정한다. 첫 실행은 배정 영역 안의 작은 부분으로 확인하고, 성공하면 해당 영역으로 확대한다.

첫 배정은 도엽 단위가 간단하다. 같은 도엽을 나누면 같은 원본의 픽셀 Polygon을 작업 JSON으로 고정한다. 원본을 잘라 새 파일로 만들 필요는 없다. 픽셀 좌표는 좌상단 기준 x 오른쪽/y 아래다. 미리보기 좌표를 원본 픽셀로 환산하고 영상 크기 안인지 확인한다. 서로 다른 도엽도 지리적으로 겹칠 수 있으므로 도엽명이 다르다는 이유만으로 시설이 다르다고 간주하지 않는다.

## 담당자가 유지할 배정표

공유 문서 하나에서 담당자가 배정하고 상태를 갱신한다. AI들이 각자 남의 진행을 알거나 자동으로 작업을 선점한다고 가정하지 않는다.

| 작업 ID | 목적 | 담당자 | 원본 파일·SHA256 | 영역/job 파일 | 코드 커밋 | 상태 | 결과 bundle_id·전달 위치 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| REPRO-A | 같은 작은 영역 재현 | A | 배정 시 기입 | 공통 job.json | 공통 SHA | 미시작 | 완료 후 기입 |
| REPRO-B | 같은 작은 영역 재현 | B | REPRO-A와 같음 | 공통 job.json | 공통 SHA | 미시작 | 완료 후 기입 |
| AREA-A | 구역 확장 | A | 배정 시 기입 | area-a.json | 공통 SHA | 미시작 | 완료 후 기입 |
| AREA-B | 구역 확장 | B | 배정 시 기입 | area-b.json | 공통 SHA | 미시작 | 완료 후 기입 |

상태는 미시작 → 진행 중 → 완료 또는 실패/보류로 기록한다. 예시 행은 실제 배정이 아니다. 한 라운드 중에는 같은 커밋과 기본 설정을 유지하고, 업데이트하거나 모델·점수를 바꾼 실행은 별도 비교로 기록한다. 작업 ID는 운영용 이름이며 현재 후보 스키마의 자동 배정 필드가 아니다. `area.name`, job 파일과 결과 보고서에 함께 적는다.

## 경계와 결과 수집

분석 영역은 담당 범위로 나누되 추론의 margin·타일 overlap은 유지한다. 경계 문맥을 없애면 횡단보도가 잘릴 수 있다. 경계의 중복 후보는 정상적으로 발생할 수 있으므로 관측을 삭제하거나 후보 수를 시설 수로 합산하지 않는다. `boundary` 및 `possible_duplicates`는 검토 단서이며 저장소를 넘는 중복 해소가 완료됐다는 뜻은 아니다.

각 참여자는 결과 폴더 전체(후보 JSON/GeoJSON, 근거 PNG, manifest, started.json), 사용한 job JSON, 실행 명령·코드 커밋·환경·소요 시간·문제 기록을 지정된 비공개 전달 경로로 보낸다. 근거 이미지 공유 권한은 별도로 확인한다. 재실행은 새 출력 폴더로 구분한다. 같은 묶음의 중복 수신은 bundle_id로 구분하고, 다른 실행 간 같은 원본은 SHA256으로 확인한다. 경계의 동일 시설 대응은 후속 검수에서 판단한다.

현재 자동 통합 importer나 분산 실행 조정은 이 저장소에 없다. 사람 담당자가 배정표와 묶음을 관리한다. 재현성·개발 비교 결과를 독립 평가 결과와 섞지 않고, AI 관찰·사람 검수·관측 불가 상태를 따로 기록한다.
